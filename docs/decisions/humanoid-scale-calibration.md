# 人形角色 humanoidScale() 校正——廚師「比例比別人小一號」事件

## 現行規則（2026-09-01）

人形角色的 `HUMANOID_WORLD_HEIGHT = 1` 現在明確定義為**鞋底到頭骨頂端**，
也就是頭部球體／頭部幾何本體的最高點。瀏海、髮帽、長髮、辮子、呆毛、帽子、
羽毛與其他頭飾都只是裝飾，可以超出 1 世界單位，但不得計入
`humanoidScale()` 的輸入高度。

選角卡或其他人物預覽同樣要使用這組人體基準框取景；不能用包含頭髮與頭飾的
完整 `Box3` 為每個角色各自算鏡頭。曾發生男女主角本體尺寸相同，但男角呆毛
較高，完整包圍盒使其預覽鏡頭拉遠，畫面上反而顯得比女角小的問題。

新模型的做法：

1. 確認鞋底基準為 `y = 0`。
2. 以頭部幾何的中心、半徑及 Y 縮放精確算出頭骨頂端。
3. 用「頭骨頂端－鞋底」呼叫 `humanoidScale()`；不要量髮型最高點。
4. 若模型會出現在獨立預覽中，記錄 `humanoidHeightFrame`，讓所有外型共用
   相同的鞋底／頭骨取景範圍。

以下內容保留為舊問題的歷史診斷；其中「把髮梢最高點統一為 1」已被上述規則
取代，僅供理解當時廚師模型為何看起來縮小。

## 症狀

2026-08-27，Zeppelin 用截圖回報新建的廚師(`makeChef()`)站在其他 NPC
旁邊時，明顯矮/小了一號，問是否要查根因並記錄。

## 系統背景

`src/humanoid.ts` 每個角色最後都會呼叫

```js
group.scale.setScalar(humanoidScale(unscaledHeight));
// humanoidScale = (h) => HUMANOID_WORLD_HEIGHT / h;  // HUMANOID_WORLD_HEIGHT = 1
```

把整個角色從腳底到頭頂/髮梢最高點，統一等比例縮放成同一個世界高度
(`1`)。`unscaledHeight` 這個參數必須是「這個角色自己建模當下、最高點的
真實 y 座標」——這個數字只能靠建模者自己量出來，不是系統自動算的，量錯
會讓整個角色等比例縮小或放大。

## 根因（兩個都有，第二個是主因）

1. **十二面體(Dodecahedron)頂點高度算錯，約 2% 誤差，不是主因**：廚師的
   雙層丸子頭用 `THREE.DodecahedronGeometry` 做。一開始估算頂點最高點時
   誤用了球體的算法(中心 y + 半徑)，但 three.js 建構十二面體時所有頂點
   會正規化到同一個外接半徑，最高的頂點方向其實只到半徑的
   `1/√3 ≈ 0.577`，不是完整半徑。這個算錯只造成大約 2% 的高度誤差。

2. **頭髮占總高度比例過高，才是主因**：抓對真實頂點高度後，發現雙層
   丸子頭把「頭頂到最高點」這段距離撐得比其他角色都高很多——廚師頭髮
   占總高度比例約 24%，木匠/村長大概是 20%。`humanoidScale()`
   是把「頭到腳」整段壓進同一個世界高度，頭髮占比越高，身體(肩膀以下、
   實際決定「看起來多大」的部分)在最終畫面分到的空間就越少，人看起來
   自然比同樣都是「頭頂到腳=1 世界單位」的其他角色矮一截——即使
   `unscaledHeight` 這個校正參數本身抓得完全準確，這個「矮一截」的效果
   依然存在，因為問題不是校正錯誤，是頭髮設計本身占掉太多「總高度
   預算」。

順便發現廚師的靴子/鞋底沒有像木匠、村長那樣精準落在腳部支點(pivot)的
`y=0` 基準上，多探了 0.035，也一起修正，避免腳底沉進地面一點點。

## 修法

- 兩顆糰子頭尺寸略縮小(半徑 0.11/0.08 → 0.10/0.075)、位置降低，堆疊時
  留自然重疊，把「頭髮占總高度比例」壓回跟木匠/村長同一個量級(~20%，
  精確算出來是 20.1%，跟木匠的 19.8%、村長的 20.8% 同一個範圍)。
- 靴子/鞋底 y 位置整組上移 0.035，讓腳底精準落在 pivot 的 `y=0`。
- 用 Python 腳本(以正確的球體/十二面體頂點公式)實際算出新的最高點座標
  `1.364`，取代原本憑印象抓的 `1.47`，`humanoidScale(1.364)`。

驗算：新的最高點縮放後落在 `0.99998`(≈1，跟其他角色一致)，腳底縮放後
落在 `0.0`(精準貼地)，身體(腳到頭中心)占總高度比例 `0.799`，跟木匠的
`0.802`、村長的 `0.792` 幾乎一致。

## 教訓——之後新角色要注意

以後新角色如果頭髮、帽子、頭飾之類的裝飾比一般角色更高聳(例如誇張的
帽子、羽毛、高聳的髮型)，`humanoidScale()` 的校正參數不能只抓「頭部
本身」的高度隨便加一點估計數字：

- 要嘛老實把最高點的裝飾也精確算進去，用實際幾何公式而不是憑印象抓
  (十二面體的頂點高度尤其容易估錯，見上面第一個根因)。
- 更重要的是控制裝飾本身不要占掉太高比例的「總高度預算」——經驗值是
  頭髮/頭飾占總高度不要超過 ~20~22%，超過太多的話，即使校正參數本身算
  得完全精確，角色跟其他人並排站的時候身體還是會明顯矮一截。
- 有疑慮的話，可以照這次的做法寫一個小 Python 腳本，用正確的幾何公式
  (球體：中心+半徑×縮放；十二面體：中心+半徑×(1/√3)×縮放；箱型/圓柱：
  中心±高度/2)算出真正的最高點跟最低點，再回頭比對「腳到頭中心」占
  「腳到最高點」的比例，抓 0.79~0.80 這個範圍(參考木匠 0.802、村長
  0.792)，而不是用眼睛在程式碼裡估。


## 後續：比例修好後又冒出「禿頭＋頭髮蓋到眼睛」(2026-08-27)

上面這輪比例修正把兩顆糰子頭縮小、位置降低之後，Zeppelin 截圖回報新問題：
頭頂露出膚色（禿頭）、而且頭髮蓋住了眼睛。這是縮小糰子頭這個動作本身的
副作用，不是比例修正的算法錯——糰子頭變小之後，原本靠糰子頭「順便蓋住」
的頭頂縫隙跟臉部就露出來了。

實際根因（一樣用 Python 腳本算精確幾何，不是憑印象）：

- `hairCap`（頭頂那顆扁球體）本身頂點只到 `1.2622`，但頭骨球體自己的
  頂點到 `1.30`——中間有 0.038 的縫隙，縮小前是被糰子頭蓋住，縮小後蓋
  不到了，露出膚色。
- `hairCap` 是完整、未裁切的橢球體（球體 geometry 預設就是全罩住一圈，
  沒有「正面挖洞露臉」這種事），而且它的 z 方向半徑（0.212）本身就比
  臉本身還大；因為中心點 y=1.135 太接近眼睛高度 y=1.12，橢球體在眼睛
  這個高度往前凸出到 z=-0.2005，比眼睛自己的 z=-0.183 還要靠前——頭髮
  在幾何上真的疊在眼睛前面，不是視覺錯覺或穿模。

修法：只調整 `hairCap` 自己的 scale/position，完全不碰糰子頭或
`humanoidScale` 校正值：

- `scale.set(1.02, 0.6, 1.0)` → `scale.set(1.02, 0.75, 0.75)`：y 方向拉高
  讓橢球體變得更「立」，z 方向縮小減少整體前凸幅度。
- `position.set(0, 1.135, 0.01)` → `position.set(0, 1.16, 0.01)`：中心點
  抬高，讓橢球體的「腰身」（水平半徑最大的地方）離開眼睛/眉毛的高度，
  改用赤道以下比較窄的下緣去蓋眼周附近。

驗算（`~/verify_chef_hair_fix.py`）：新的 hairCap 頂點 `1.319` > 頭骨頂點
`1.30`（禿頭補上，留 0.019 餘裕）；在眼睛/眉毛/鼻子高度，hairCap 的前緣
分別留了 0.039／0.039／0.048 的安全距離，不再蓋到臉；hairCap 新頂點
`1.319` 仍然低於 `bunUpper` 的頂點 `1.364`，所以**這輪修正完全不影響
`humanoidScale(1.364)` 這個校正值**，不用重新校準比例。

### 教訓補充

同一顆角色身上如果有兩層裝飾（這裡是「髮帽 hairCap」+「疊起來的糰子頭」），
改動外層那層（糰子頭）的尺寸時，要連帶檢查內層（髮帽）原本是不是靠外層
「順便蓋住」某些破綻（頭頂縫隙、可能的穿模）——這類靠疊層蓋住瑕疵的做法
很省事，但一旦其中一層被獨立調整，瑕疵就會直接曝光。比較保險的做法是讓
每一層自己的覆蓋範圍都經得起檢驗（用幾何公式算頂點/前緣座標，跟五官座標
比對安全距離），不要依賴「反正上面還有一層蓋著」。

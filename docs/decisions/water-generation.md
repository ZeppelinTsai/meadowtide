# 湖面／海面水體生成規則

> 從 `AGENTS.md` 搬過來的架構/設計決策，仍然有效——這份同時也是硬規則，改水體/岸線前務必看。


- 水體碰撞與視覺必須共用同一份最終資料：格狀海域以 `MAPS.<map>.tiles` 的
  tile `9` 為準；湖泊等曲線水體以 `isInsideLakeShape()` 這類純形狀函式為準。
  禁止在 `build-map.ts` 另抄一份岸線座標或重新推算另一個輪廓。
- 透明水面不可按「南海／西海／新增切除區」分批各畫一層後互相重疊。透明
  mesh 重疊會因 alpha 疊加形成淺藍矩形殘影，看起來像海底仍有舊地板。
  `oldVillage` 的做法是掃描最終 tile，每列把連續 tile `9` 合併成一段水面；
  同一海格只能有一層水面與一層深度遮罩。
- 把沙灘／陸地改成海時，順序必須是：先完成所有沙地與切除區 tile 重繪，
  再從最終結果生成水面。不得在水面建好後另外疊補一塊矩形水面；若地板幾何
  會露出，應依同一輪廓切分底板，而不是用更多透明水面遮蓋。
- 修改湖岸或海岸後必跑 `npm run map-debug -- --map=<name> --legend`、
  `npm run test:map-tools` 與 `npm run build`，並在實際 3D 畫面確認沒有透明
  重疊色塊、岸線穿插或可走沙地／不可走海面不一致。
- 拍岸浪花也必須讀最終 tile 的沙地 `8`／海面 `9` 鄰接邊界，不得另抄
  一份岸線座標。南岸使用 `findSouthernShoreSandZ()`、西岸使用
  `findWesternShoreSandX()`（`src/shore-foam.ts`）；`makeFoam()` 的
  `waveDirection` 必須朝陸地，南岸另旋轉 `rotationY=Math.PI/2` 讓浪花沿
  東西向岸線延伸。修改岸線或浪花範圍後同樣執行上述三個驗證命令。
- `foamMeshes` 登記生活區、港口與舊城鎮的拍岸浪花，必須在 `buildMap()` 開頭清空，
  再由目前地圖的建圖分支重建。泡沫可以逐幀播放，但不得因此恢復港口或舊城鎮
  的整片海面頂點動畫。
- 港口與舊城鎮只保留靜態海面與平面天空反射，不做頂點上下起伏、水平推移、
  `crest` 白峰或動態法線重算；拍岸 `foamMeshes` 是獨立演出，可保留。兩張擴張地圖的海格量太大，
  逐頂點動畫會造成明顯效能損失；而低密度網格先做白峰門檻再插值，會形成按
  波長排列的灰色／綠色葉片狀亮塊。這些規則只保留在生活區 `oceanMesh`。
- 港口／舊城鎮的 tile 9 仍必須使用 `src/tile-sea-geometry.ts` 合成單一索引
  網格並共享邊界頂點，避免透明面重疊與接縫；靜態海面每世界單位只需一個面，
  不得為已移除的動畫保留二分割或四分割網格。
- 湖海共用 `src/water-reflection.ts` 的單一 XZ 平面鏡射：從實際渲染相機
  跨水面建立鏡像相機，再把同一張反射貼圖投影回所有既有水面材質。第一／第三人稱
  必須走同一入口。oblique near-plane clipping 只適用透視相機；第三人稱正交相機
  必須保留原始正交投影矩陣，否則會把投影座標扭曲成亮色多邊形。
- 反射每兩幀最多額外渲染一次 1024×576（16:9）；反射 pass 暫時隱藏所有
  已登記水面、地圖地表／建築、NPC、動物與玩家，只讓天空、星空、雲與天體
  參與取樣。這能避免草地、屋頂與船體被鏡射成綠色／白色塊。禁止每塊水面
  各建 Reflector，也禁止為反光另疊透明水面 mesh。
- 真正平面反射啟用後必須移除舊的逐頂點隨機星光著色，避免兩套效果疊加成
  方形亮磚；反射貼圖維持線性取樣，兼顧星點輪廓與成本。
- 反射投影座標只能讀世界 X/Z，Y 固定為共用水面高度；不可使用波浪動畫後的
  頂點 Y，否則低模三角面會把星點拉成直條／磚塊。一般星點需使用柔邊 alpha
  貼圖。
- 平面反射強度依水面透明度調整：淺湖保留較多本體色，深海反射較強。湖底色
  必須比海洋明亮，海洋深度層也不可接近純黑，避免夜間俯視呈現無底黑洞。

# 作物模型：蘿蔔／馬鈴薯／番茄各自造型，取代種子袋貼紙

## 背景

`makeCropMesh(stage, cropType)`（`props-resources.ts`）本來就有 `cropType`
參數，`farm-visuals.ts` 種田時也确实把 `c.cropType ?? "radish"` 傳了進去，
但函式本體在成熟株（`stage >= 2`）完全沒有用到這個參數，一律長成同一叢
番茄（莖 + 3 顆紅色球體果實）——蘿蔔、馬鈴薯種下去，長大後外觀跟番茄
一模一樣。這是 2026-09-01 Zeppelin 要求「幫蘿蔔、馬鈴薯、番茄建模」時
盤點才發現的既有 bug，順手修掉。

同一輪也處理了另一個相關但獨立的問題：種子袋（`makeSeedPouch()`）原本
用一張 canvas 畫的「貼紙」(`drawSeedStickerCrop()`，平面貼圖，蘿蔔/馬鈴薯/
番茄各畫一張圖案)當作牌子貼在袋子前面。平面貼紙只有一個面看得到圖案，
握持（角色手上）、縮圖快取（背包/快捷列共用）、地圖上三個情境各自的
相機角度不一樣，需要各自校正貼紙面向哪個方向——上一輪先誤改了握持那顆
獨立模型的旋轉，又發現真正該調的是縮圖那邊，來回調整了兩次角度
（見 `docs/decisions/item-display-scale.md` 的「背包的轉向不對」段落），
调一次只解一個相機角度，換個情境又不對，治標不治本。

## 修法

**成熟株分岔造型**（`makeCropMesh()`，`props-resources.ts`）：`stage >= 2`
時依 `cropType` 分成三個獨立分支——

- 蘿蔔：淡粉色橢球根部 + 綠色莖 + 5 片環狀排列的葉片，呼應舊貼紙的
  「淡色根部＋扇形葉片」設計語彙。
- 馬鈴薯：橢圓形褐色塊莖(壓扁的球體) + 2 顆淺色小凸起(芽眼) + 一小截莖與
  兩片捲葉(呼應舊貼紙「還帶著一點發芽」的畫法)。
- 番茄：維持既有造型(莖 + 3 顆紅色球體果實)不動，只是從「其他情況一律
  用這個」的隱性預設，改成 `cropType === "tomato"` 的明確分支。

三種共用 `stage 0`(幼苗)、`stage 1`(發芽) 的通用造型，沒有跟著分岔——
幼苗階段本來就看不太出作物差異，不用提早分家。

**種子袋改用立體模型**（`makeSeedPouch()`）：整段 canvas 貼紙繪圖
(`drawSeedStickerCrop()`)刪掉，改成直接呼叫同一顆
`makeCropMesh(2, cropType)`，縮小(`scale.setScalar(0.55)`)放在袋口上方
(`position.y = 0.2`)，就像袋子裡的種子長出了一小株成熟作物探出來。跟
`farm-visuals.ts` 種在農地裡的成熟作物是同一份模型、同一個資料源——之後
要改造型，兩邊會一起變，不用兩處分別維護。

**移除縮圖旋轉補丁**（`renderModelThumbnail()`，`inventory-ui.ts`）：
上一輪為了讓貼紙面向縮圖相機加的 `if (item.id.endsWith("Seeds"))
model.rotation.y += Math.PI / 4` 整段拿掉。立體模型從縮圖相機的固定
3/4 俯角看基本都認得出形狀，不像單張貼紙只有一個面有圖案，理論上不需要
再為了「哪個面朝哪個相機」個別校正旋轉角度；如果 Zeppelin 進遊戲後仍覺得
某個角度不夠好看，屆時再調也比之前單純，因為模型本身立體，怎麼轉都不會
「轉到看不到牌子」。

## 待確認

- 這輪只動了成熟株(`stage >= 2`)；如果之後想讓幼苗/發芽階段也分作物
  差異化，是新的一輪工作，不在這次範圍內。
- `makeInventoryItemVisual()` 的 `"harvested"`(通用「農作物」堆疊，不分
  蘿蔔/馬鈴薯/番茄，見 `item-catalog.ts`)目前仍呼叫
  `makeCropMesh(2)`，沒有帶 `cropType`，函式簽章預設值是 `"radish"`，這輪
  修完之後這個通用道具圖示會固定顯示蘿蔔造型——這是既有設計(一個籠統
  堆疊道具本來就沒有單一「該用哪個造型」的正確答案)，這輪沒有改動也不
  在这次需求範圍內。
- 縮圖旋轉拿掉之後實際好不好看，仍要 Zeppelin 進遊戲看一次確認；這台
  機器這輪一樣卡在已知的 EPERM 檔案鎖定，沒辦法自動截圖驗證。

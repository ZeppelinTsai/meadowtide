# 事件演出鏡頭級距

> 從 `AGENTS.md` 搬過來的架構/設計決策，仍然有效。


- gameState.zoom 的正式語意級距固定為：**特寫 2、中景／一般遊玩預設
  5、遠景 10、特殊演出最大 20**。事件、過場或劇情鏡頭應優先從這四個值
  選擇，不要在事件函式裡散落新的任意 zoom 數字。
- 2 用於角色表情或單一物件特寫；5 是正常探索與一般對話中景；10 用於
  同時交代角色與場景的遠景；20 只給外海航行、大型地標或其他必須展示
  大範圍場面的特殊演出，不是一般地圖的預設值。
- 鏡頭事件結束時必須還原事件開始前的 zoom，或明確回到預設 5；不得把
  特殊鏡頭值永久留給玩家。使用滾輪／雙指縮放時仍須經 input-save.ts 的
  setCameraZoom() 夾限；事件系統日後應抽共用鏡頭函式，不要直接在多個
  事件內各自改 camera.left/right/top/bottom。

## 2026-08-27：手動試鏡頭(F4)的下限放寬到 0.05(儘可能近)

上面四個級距(2/5/10/20)是給「寫進事件程式碼」選的固定值，不要發明新
數字——這件事沒變。但 Zeppelin 反饋鏡頭調整模式(F4，見
`docs/decisions/cutscene-camera.md`)能拉近的極限不夠，想要跟第一人稱
(`first-person-camera.ts`)貼近角色的程度一樣近，方便直接在裡面試演出
構圖。`input-save.ts` 的 `setCameraZoom()` 原本把 `gameState.zoom`(也就
是正交相機 `camera.top`/`camera.bottom` 的絕對值)下限夾在 `2`，過程
分三步降下來：

1. 先降到 `0.5`。
2. Zeppelin 問「能特寫到整張臉甚至瞳孔嗎」，估過角色頭部尺寸(半徑約
   0.205、縱向 scale 1.08、總高度約 0.44)後降到 `0.25`，抓的是「整張
   臉框滿畫面、留一點邊距」的框法。
3. Zeppelin 澄清：不是真的要看「瞳孔」這個部件，意思是儘可能特寫到看
   得清楚眼睛，而且目前的低模眼睛模型之後可能會換掉——不用因為現在
   模型在極限特寫下不好看而保守。查過這套系統沒有「太近會撞到角色」
   這種物理限制(正交相機的 `zoom` 只決定 frustum 半高，`camDist` 另外
   算、永遠 ≥16 世界單位，跟 zoom 無關)，理論上能趨近 0，但趨近 0 沒
   有實際意義(畫面收斂成一個點)。最後定案 `ZOOM_MIN = 0.05`(總高度
   0.1 世界單位，量級大概是這顆角色單眼含眉毛的高度)，當作「已經沒有
   再往下用途」的下限。

**瞳孔本身沒有跟著做**：`humanoid.ts` 目前每個人形角色（船長、玩家、
村民）的眼睛都只是一顆沒有分虹膜/瞳孔、沒有貼圖的低模橢圓球
(`SphereGeometry` 半徑約 0.017~0.018、只有 6×4 分段)，鏡頭拉多近都只
會把這顆小橢圓球放大看到低模稜面。之後如果真的需要看得到瞳孔的特寫，
得回頭幫眼睛加建模(分虹膜/瞳孔或貼圖)，屬於另一件事，這次沒有動。

這只是放寬「手動試鏡頭時滾輪/F4 能碰到的範圍下限」，`2` 這個「特寫」
官方級距本身沒變、事件程式碼要用還是照樣用 `2`。這套系統的相機投影方式
是正交、固定傾角(`TILT_RAD`)，跟第一人稱的透視相機、可任意旋轉貼臉是
兩回事，貼太近有機會看到低模角色/場景沒有特別為「近距離看」處理過的
接縫或背面(`cutscene-camera.md` 開頭就提過這個取捨，Zeppelin 也已確認
現階段不在意這件事)——放寬下限只是讓 Zeppelin 能親自用 F4 試出想要的
構圖，不代表 `0.05` 這個極限值本身適合直接寫進事件，實際要用之前務必
先用 F4 試一輪看畫面。
